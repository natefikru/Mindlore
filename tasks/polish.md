# Polish: closer to Apple's guidelines, and more impressive

The app ships free (owner, 2026-09-27; context in `~/Downloads/mindlore-ship-free-plan.md`), so this is about how it feels in the hand and what it does outside its own screens, not monetization. Each item comes from reading the whole HIG against the iOS build (`docs/design/apple-hig.md`, rules with numbers in `docs/design/hig-notes/`), and each was checked against the code on 2026-09-27. Read the linked notes section before starting an item.

Checked and already fine, so not here: the API key is a `SecureField`; recording uses `.record`, so the silent switch can't drop it; Reduce Motion is read by `Motion`, `MindView`, and `SearchPanel`; Today's card row hides its scroll indicator; progress copy is already specific. Staying as it is on purpose: the + over the tab bar (owner, 2026-09-24), the per-app appearance switch, no Dynamic Type passes.

## Phase 1: first impression

- [x] **App icon in Icon Composer.** (Generated, not hand-drawn: `Mindlore/AppIcon.icon` from `scripts/design/icon.swift`, checked in all six appearances with Icon Composer's `ictool`; still to see on the phone.) Today it is three PNGs (`AppIcon.png`, `-dark`, `-tinted`) drawn by `scripts/design/icon.swift`. iOS 26 icons are layered `.icon` files, and the system renders the clear and tinted looks and the glass edge from the layers; a PNG gets a flat approximation. Split the existing design (ember disc, dark paper, seven nodes reading as an "m" and a waveform) into background, disc, and node layers, author it in Icon Composer, and check all six appearances on a phone. Owner judgment on the result. Notes: `1-visual-foundations.md`, App icons.
- [x] **Increased-contrast colors.** (PR #72: high-contrast pairs at 7:1, and the default light variants deepened to 4.5:1 on the owner's go-ahead, 2026-09-28; glyphs on ember take Paper.) None of the 20 color sets in `Assets.xcassets` (Paper, Card, Ink, the nine Area, seven Kind, AccentColor) has a high-contrast variant, so Settings > Accessibility > Increase Contrast changes nothing in the app. Add one per light and dark pair, aiming at 4.5:1 for text (7:1 for small text in custom colors). This is the one gap the HIG states as a requirement. Done when a side-by-side with Increase Contrast on shows every chip, badge, and label getting stronger. Notes: `1-visual-foundations.md`, Color; `2-behavior.md`, Accessibility.
- [x] **Ask for a review at the right moment.** (Built on `feature/review-prompt`: `Mindlore/Reviews/ReviewPrompt.swift`, three days after install, once per version, at a full Life reading or the tenth finished entry.) Nothing calls `requestReview` today. Ask once after a moment of value, such as the first Life reading or the tenth finished entry, never during the first session, never in the middle of writing or recording. The system caps it at three a year, so no bookkeeping of our own beyond "not before X". For a free app ratings are the main way people find it. Log `review.requested` with the trigger only. Notes: `4-input-and-system.md`, Ratings and reviews.

## Phase 2: Mindlore outside its own screens

All of these reuse the App Intents in `Mindlore/Intents/MindloreIntents.swift` (Start Recording, New Written Entry, Ask Your Journal), so each is mostly wiring. Most need a widget extension target, which is the one real setup cost; do it once for all three and check signing on the runner (`release.yml`) and the device scripts.

- [x] **Control Center, Lock Screen, and Action button control for Start Recording.** (Built in `MindloreWidgets`; phone step 41.) A button control (not a toggle: recording is not a state you flip from Control Center) that opens straight into recording. One press to capture from anywhere is the biggest wow for the effort in this whole plan. Notes: `4-input-and-system.md`, Controls.
- [x] **Live Activity while recording.** (Built; seen in the simulator's Dynamic Island; phone step 42.) Lock Screen and Dynamic Island show "Recording" and the elapsed time, with Stop as its one control. Never any words: journal text is what the HIG says to keep off the Lock Screen. Start with `RecordingSession`'s real recording (not a ready recorder), end it the moment `stop()` runs with no lingering dismissal, and make sure a force-quit mid-recording (which `MindloreApp.init` recovers) doesn't leave an orphaned activity. Needs device smoke steps and diagnostics events. Notes: `4-input-and-system.md`, Live Activities.
- [x] **Home Screen quick actions.** (Record, New Entry, Ask; the fourth slot left empty; phone step 43.) Long-press the icon: New Entry, Record, Ask, and a fourth slot (Reflect, or the open loose end Today would lead with). Route through `IntentRequests.shared` like the intents do, so cold and warm launches behave the same. Notes: `4-input-and-system.md`, Home Screen quick actions.
- [ ] **Widgets.** Two to start: a Record widget (interactive button, small and Lock Screen accessory sizes), and the loose end Today would open on, deep-linking to it. The loose-end widget shows text on the Home Screen, so decide with the owner whether it hides the text when the phone is locked and when `AppLock` is on. No streaks, no counts meant to make anyone feel behind; About already refuses streaks. Widgets read the shared store, so this is where an App Group and the CloudKit container have to be thought through first. Notes: `4-input-and-system.md`, Widgets.

## Phase 3: finish

- [x] **Never color alone.** (Checked 2026-09-29, nothing to fix.) Went through Life's area bubbles (`LifeBubbleField`), Life's area cards (`LifeCard`, `LifeSentenceRow`, `LifeFollowRow`, `LifePriorityBar`), and Reflect's Recaps (`ReflectMonthRow`, `ReflectWeekSection`, `ReflectMoodChipStrip`). Every area color already sits next to the area's name or its symbol (a bubble always shows its name text; `LifeSentenceRow`, `LifeFollowRow`, and the priorities picker all pair `area.symbol` with `area.color`), and every mood dot already sits next to the mood's word (`ReflectMoodChipStrip`). Recaps carries no area or mood color at all. Kind colors on Mind already have the badge text and the tag pin's size, as noted above. Notes: `2-behavior.md`, Accessibility; `4-input-and-system.md`, Charts.
- [x] **Say it was wrong.** (PR, 2026-09-29: `AnswerFeedback` in `Mindlore/Reflect/AnswerFeedback.swift`.) A thumbs up/down on an Ask answer's footer and on an entry's insights status card, next to "Sends this entry to OpenAI". Tapping the same one again clears it; the other replaces it. Stored and counted only, the way Life's "That's right"/"Not quite" works: `ReflectSummary` rows under `ask.feedback`/`insights.feedback`, no CloudKit schema change, never read into a prompt. Logs the verdict and the surface only. Notes: `2-behavior.md`, Generative AI.
- [x] **Welcome screen.** (Checked 2026-09-29, no change.) `WelcomeView`'s "I have an OpenAI key" stays as the quiet secondary action it already is: it opens Settings' AI screen rather than asking for a key inline, so onboarding itself still has no key step. The ship-free plan's concern was a key step blocking onboarding, not this button's existence.

## Order and size

Phase 1 is small and matters before the listing goes up; the icon needs the owner's eye. Phase 2 starts with the extension target, then the control (smallest), the Live Activity, quick actions, and widgets last since they need the shared-store decision. Phase 3 can go in any gap. Every item gets its own small PR, unit tests where there is logic (the review trigger, quick action routing, the Live Activity's start and end rules), and phone steps in `tasks/smoke-test.md` where only a device can show it.
